  <action>
1. Add two columns to the customers table via direct SQL (use supabaseDb.supabase.rpc or raw query):
   - `last_login_at` (timestamptz, nullable) -- last time the user logged in
   - `login_count` (integer, default 0) -- total login count
   Run this as a one-time migration at the top of auth.js module load (wrapped in try/catch, idempotent using IF NOT EXISTS pattern via ALTER TABLE ADD COLUMN IF NOT EXISTS).

2. In the `/api/auth/me` handler, AFTER the successful customer fetch (line ~60, after `const { data: customer, error } = customerRes`), add login tracking with 1-hour deduplication:
   - Compare `customer.last_login_at` to now. If null OR more than 1 hour ago, fire an async (non-blocking, no await) update:
     ```js
     supabaseDb.supabase
       .from('customers')
       .update({
         last_login_at: new Date().toISOString(),
         login_count: (customer.login_count || 0) + 1
       })
       .eq('id', dbCustomerId)
       .then(() => {})
       .catch(err => console.error('Login tracking error:', err));
     ```
   - This is fire-and-forget -- do NOT block the /me response.
   - Do NOT track login when `req.user.isImpersonating` is true (admin impersonation should not count as student login).
   - The 1-hour dedup means: the 60s auth cache may serve cached responses, but even when cache misses, we only update login tracking if last_login_at is >1 hour old. This prevents inflated counts from page refreshes.

3. Include `lastLoginAt` and `loginCount` in the /me response object (alongside existing fields like `policiesAcceptedAt`):
   ```js
   lastLoginAt: customer.last_login_at || null,
   loginCount: customer.login_count || 0,
   ```
